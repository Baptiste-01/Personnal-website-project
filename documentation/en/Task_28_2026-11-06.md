# Task 28: Real-Time Arena Player Counter Synchronization and Leave Handling

- **Date:** 2026-11-06
- **Author:** Antigravity & Baptiste-01
- **Status:** Completed

---

## Objective

1. **Fix Stuck Arena Player Counter in Lobby**:
   - Resolve the issue where an arena displayed `1/8` (or any number greater than 0) in the lobby even after all participants had left the arena or closed their browser.
2. **Explicit Player Leave Handling (`leave`)**:
   - Allow a player clicking "Back to lobby" or "Main lobby" to immediately leave the arena room without waiting for the 45-second reconnection grace period.
3. **Count Active Online Players Exclusively**:
   - Ensure arena listing endpoints (`GET /arenas` and `GET /arenas/:id`) and database persistence reflect only currently active online players (`getActivePlayerCount()`), rather than total in-memory room size which included disconnected sessions.
4. **Dynamic Real-Time Lobby Auto-Refresh**:
   - Introduce seamless background polling (`silent` mode every 3 seconds) in the Lobby page so that player counts and arena statuses update automatically without requiring manual user intervention.

5. **Replace Inert "En attente de l'hôte..." Button with Large "Ready" Button**:
   - Replace the disabled bottom-right button for guests with an interactive primary action button to toggle ready/unready status directly, eliminating the need to click the small card badge.

---

## Root Causes Identified

1. **Use of `room.players.size` Instead of `room.getActivePlayerCount()`**:
   - In `apps/api/routes/arenas.ts`, the route returned `players: room ? room.players.size : a.players`.
   - The memory manager retained disconnected players for a 45-second grace window (`player.isOnline = false`). During that window, `room.players.size` remained 1, incorrectly advertising `1/8` in the lobby.
2. **Missing `leave` Protocol for Intentional Exit**:
   - The frontend emitted no `leave` event when returning to the Lobby via exit buttons (`#back-to-lobby` or `#leave-to-lobby`). The server treated every disconnection as an accidental network drop and waited 45 seconds before removing the player.
3. **No Automatic Lobby Refreshing**:
   - The Lobby component only loaded arenas once on mount (`useEffect`), making it impossible to see player count updates in real time without clicking "Actualiser".
4. **Database State Not Synchronized on Memory Eviction**:
   - The `removePlayer` method in `GameRoom` deleted the player from the in-memory map but did not persist the updated count to Prisma (`prisma.arena.update`), occasionally leaving orphan counts behind.
