# Task 42: Fix Mythologie & Légendes Category Remaining Active by Default When Unselected

- **Date**: 2026-11-27
- **Author**: Antigravity & Baptiste-01
- **Status**: Completed

## Objective

The **Mythologie & Légendes** category remained active in games even when it appeared unselected in the arena or lobby configuration UI. The goal was to trace the root cause and fix it cleanly.

## Action Plan

1. Trace category ID handling across default settings (`'mythologie'`, `'capitale'`, etc.), `/questions/categories` API responses (`'Mythologie & Légendes'`, `'Capitales'`, etc.), and React state in `Arena` and `Lobby`.
2. Add canonical category helpers in `apps/web/src/utils/tagFilter.ts` (`hasCanonicalCategory`, `toggleCanonicalCategory`, `normalizeCategoriesToAvailable`) backed by `getCanonicalClientCategoryKey`.
3. Update `Arena/index.tsx` and `Lobby/index.tsx` to normalize aliases on fetch and check/toggle selections by canonical key.
4. Verify TypeScript checking and production bundling with `bun run --cwd apps/web build`.

## Implementation

- **Root Cause**: Default settings (`defaultSettings.categories` in `Arena`, `roomManager.ts`, `DEFAULT_GAME_SETTINGS`) initialize categories with legacy lowercase IDs (`'mythologie'`), whereas `GET /questions/categories` returns the database primary ID (`'Mythologie & Légendes'`). Because `Arena` and `Lobby` checked selection using exact `includes(catId)` and filtered only `c !== catId`, `'mythologie'` remained in `settings.categories` while appearing unchecked in the UI, and the backend expanded `'mythologie'` to `'Mythologie & Légendes'` via `getCategoryQueryVariants`.
- [`apps/web/src/utils/tagFilter.ts`](file:///c:/Users/bapti/Desktop/Moi/Projet-Perso/Personnal-website-project/apps/web/src/utils/tagFilter.ts): Added `hasCanonicalCategory`, `toggleCanonicalCategory`, and `normalizeCategoriesToAvailable`.
- [`apps/web/src/pages/Arena/index.tsx`](file:///c:/Users/bapti/Desktop/Moi/Projet-Perso/Personnal-website-project/apps/web/src/pages/Arena/index.tsx): Normalized `settings.categories` upon fetching `/questions/categories`, switched `isSelected` checks to `hasCanonicalCategory`, and updated `toggleCategory` to use `toggleCanonicalCategory` so all canonical aliases are removed when unchecking.
- [`apps/web/src/pages/Lobby/index.tsx`](file:///c:/Users/bapti/Desktop/Moi/Projet-Perso/Personnal-website-project/apps/web/src/pages/Lobby/index.tsx): Updated `toggleCategory` and `isSelected` in the arena creation modal to use `toggleCanonicalCategory` and `hasCanonicalCategory`.
- [`apps/web/src/pages/FlashGuess/index.tsx`](file:///c:/Users/bapti/Desktop/Moi/Projet-Perso/Personnal-website-project/apps/web/src/pages/FlashGuess/index.tsx) & [`apps/web/src/hooks/useArenaSocket.ts`](file:///c:/Users/bapti/Desktop/Moi/Projet-Perso/Personnal-website-project/apps/web/src/hooks/useArenaSocket.ts): The "🔄 Rejouer ensemble" button now calls `actions.startGame()` directly (with end-game state reset on `game_started`) to start a new match immediately without returning to the arena lobby.
