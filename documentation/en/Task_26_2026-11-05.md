## Objective

During large question file imports (particularly the consolidated CSV including the new Anime & Manga questions), three major issues were reported in the Admin Dashboard:

1. **Duplicates in Visual Preview Grid**:
   - Certain question cards appeared side-by-side in duplicate or triplicate in the preview grid.
   - These stemmed from both historical duplicates in the source CSV file and lack of ID deduplication in the `importedQuestions` list returned by the backend and consumed by React.

2. **Filter Dysfunction (Persistence of Cards from Other Categories)**:
   - When filtering by category (e.g. *Anime & Manga*) and status (e.g. *Ajoutées*), cards from unrelated categories (e.g. *Géographie* / *Tour Eiffel*) marked as *Mise à jour* remained rendered in the grid.
   - Duplicate cards sharing identical keys (`key={q.id}`) triggered React Fiber reconciler key collision bugs, leaving orphaned DOM nodes that failed to unmount upon filter changes.

3. **False "Updated" Status for Unchanged Questions**:
   - Existing questions matching the database records were unconditionally overwritten with `prisma.question.update` and flagged as `updated`, even when no field (text, answer, accepted answers, difficulty, image, tags, category) was changed.
   - This skewed import session statistics (e.g., 555 questions reported as updated) and produced redundant database write operations.

---

## Action Plan

1. **Backend API (`apps/api/routes/import.ts`)**:
   - Implement a `hasQuestionChanged` utility performing a deep comparison between the existing database record and incoming row data.
   - Only execute `prisma.question.update` and flag as `updated` if at least one field genuinely changed.
   - Count identical questions as `unchanged` without triggering redundant database updates.
   - Deduplicate items in `importedQuestions` by `id` to guarantee strictly unique records returned to the client.
   - Extend `ImportSummary`, `ImportResult`, and `ImportedQuestionItem` interfaces with `unchanged` and `totalUnchanged`.

2. **Frontend Admin (`apps/web/src/pages/Admin/index.tsx`)**:
   - Memoize and deduplicate `activeQuestionsList` using `useMemo` with a unique ID `Set` to prevent React key collisions.
   - Memoize `availableCategories` with case-insensitive deduplication (`trim().toLowerCase()`).
   - Automatically reset the category filter if the active category is no longer available.
   - Add a `💤 Inchangées` filter button to easily isolate unchanged questions.
   - Update the success alert and per-category summary table to report unchanged counts.

3. **CSS Styling (`apps/web/src/pages/Admin/Admin.css`)**:
   - Define styles for unchanged cards and badges: `.preview-card--unchanged` (slate border) and `.preview-status-pill.unchanged`.

4. **Data File Sanitization (`smik_party_all_questions.csv`)**:
   - Remove the 5 duplicate rows identified in the source CSV (Eiffel Tower and seasonal anime cover replicas) to maintain a pristine 864-question catalogue.

## Implementation

### 1. Backend (`apps/api/routes/import.ts`)
- Added `hasQuestionChanged` comparing question text, primary answer, accepted answer sets (case-insensitive sets), difficulty, category, image URL, and tags.
- Three-way status handling during upsert:
  - `inserted`: new question created (`prisma.question.create`).
  - `updated`: question modified (`prisma.question.update`).
  - `unchanged`: question exists with strictly identical attributes (no DB write).
- Deduplication of `importedQuestions` via `findIndex(q => q.id === ...)`.

### 2. Frontend (`apps/web/src/pages/Admin/index.tsx` & `Admin.css`)
- Type updates: `status: 'inserted' | 'updated' | 'unchanged'`.
- `activeQuestionsList` wrapped in `useMemo` deduplicating by question ID.
- `availableCategories` deduplicated without case duplication.
- Support for `previewFilter === 'unchanged'` with `💤 Inchangée` badge.
- CSS classes added in `Admin.css` for `.preview-card--unchanged` and `.preview-status-pill.unchanged`.

### 3. Data File (`smik_party_all_questions.csv`)
- Removed 5 duplicate rows. The consolidated CSV now holds 864 strictly unique records.
