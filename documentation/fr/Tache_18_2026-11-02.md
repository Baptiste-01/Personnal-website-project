# Tâche 18 : Système de sous-catégories par tags dynamiques & Responsivité mobile de l'Arène

- **Date :** 2026-11-02
- **Auteur :** Antigravity & Baptiste-01
- **Statut :** Terminé

---

## Objectif
1. **Catégorie indépendante pour la mythologie** : Dissocier définitivement *Mythologie & Légendes* de la catégorie *Histoire*.
2. **Système de sous-catégories par tags dynamiques** :
   - Exploiter la colonne `tags` des questions du template Excel `smik_party_questions_template.xlsx` (ex: `Grec`, `Romain` pour la mythologie, `Europe`, `Asie` pour les capitales).
   - Bannir tout codage en dur de tags ou questions dans le code source : la base de données et l'import Excel restent les uniques sources de vérité.
3. **Ergonomie de sélection unifiée (sans onglet séparé)** :
   - Intégrer les sous-catégories directement sous chaque carte de catégorie dans l'onglet **Catégories**.
   - Par défaut, bouton « ✨ Toutes » actif : aucun filtre de sous-catégorie n'est imposé et l'intégralité des questions de la catégorie est éligible.
   - En cas de sélection de tags spécifiques, seules les questions correspondantes sont retenues.
4. **Indicateur de volume en temps réel** : Afficher instantanément le nombre de questions éligibles selon les catégories, sous-catégories et difficultés choisies.
5. **Responsivité mobile intégrale** :
   - Résoudre les débordements et l'inaccessibilité de la modal de création d'arène sur mobile.
   - Adapter la page de configuration de l'arène (`/arena/:id`) pour les petits écrans (défilement naturel plein écran, barre des joueurs compacte, onglets textuels glissants, puces sans débordement).

---

## Plan d'action
1. **Schéma Prisma & Base de données** :
   - Ajouter `tags String[] @default([])` sur `Question` et `Arena`.
   - Créer la table `Category` (`id`, `slug`, `name`, `icon`, `tags String[]`).
   - Synchroniser le schéma PostgreSQL (`bun run db:push`).
2. **API Backend (`apps/api`)** :
   - Étendre `import.ts` pour parser, nettoyer et associer les tags Excel aux questions et aux catégories.
   - Adapter `buildWhereClause()` dans `routes/questions.ts` pour gérer le paramètre `catTags` (ex: `mythologie:Grec+Romain`) avec fallback automatique vers toutes les questions si aucun tag n'est spécifié.
   - Implémenter les routes `GET /questions/categories` (agrégation dynamique avec décompte par tag) et `GET /questions/count`.
3. **Frontend Web (`apps/web`)** :
   - Supprimer l'onglet séparé `# Tags` et les formulaires manuels superflus.
   - Afficher les puces de sous-catégories sous chaque carte de catégorie avec bouton « ✨ Toutes ».
   - Transmettre `catTags` à FlashGuess et afficher les badges de tags au-dessus des questions.
   - Refondre la responsivité CSS de `CreateArenaModal` (`Lobby.css`) et de la page d'arène (`Arena.css`).
4. **Vérification technique** :
   - Compilation TypeScript sans erreur (`tsc -b` web et `tsc --noEmit` api).
   - Validation du build Vite de production.

---

## Réalisation
- **Modèle de données dynamique** : persistance des tags sous forme de tableau natif PostgreSQL (`text[]`) requêté via l'opérateur Prisma `hasSome`.
- **Import Excel automatisé** : détection et normalisation automatique des tags (séparateurs `,`, `;`, `/`), sans aucune donnée injectée en dur dans le code source ou le seed.
- **Sélection fluide en interface** : intégration directe sous chaque carte de catégorie de puces réactives avec compteur par tag et bouton de réinitialisation rapide.
- **Affichage en cours de partie** : mise en valeur des sous-catégories dans FlashGuess via des badges discrets au-dessus de l'intitulé de la question.
- **Responsivité mobile complète** :
  - Modal Lobby : hauteur adaptative (`max-height: calc(100dvh - 32px)`), défilement interne et boutons d'actions sticky garantissant l'accès immédiat à « Créer et rejoindre ».
  - Page Arène : passage en flux continu plein écran, réduction de la hauteur de la barre des joueurs, préservation des libellés d'onglets avec défilement tactile horizontal et disposition `flex-wrap` pour toutes les puces de sous-catégories et difficultés.
- **Contrôles qualité validés** : 0 erreur TypeScript et build de production généré en moins de 500 ms.
